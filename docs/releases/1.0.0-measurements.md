# Folio 1.0 performance measurements

Same method as [0.9.0](0.9.0.md) so the figures are comparable. Nothing here is rounded in our favour: a figure over its
target is a miss, even by a little.

## Setup

- Commit: `6786d0de21bb472531f31c869bb763140a0e9fdf` (`origin/main` after PR #787), clean worktree, no engine or
  benchmark changes. Built in Release.
- Machine: AMD Ryzen 7 5800X (8 cores, 16 threads), Windows 11 (10.0.26300), .NET SDK 10.0.403, measured on 2026-11-14.
- NativeAOT content host: `tools/publish-content-host.ps1 -Destination artifacts/content-host`. NativeAOT canvas probe:
  `dotnet publish tools/Folio.CanvasFrameProbe -c Release -r win-x64 --self-contained true -p:PublishAot=true`
  (the CI step).
- Machine load: before every run a script checked that no `ffxiv*`, `Folio*`, `testhost`, `vstest` or `ilc` process and
  no `dotnet` process other than idle MSBuild node-reuse hosts was running, and that RAM use was under 85%. It never
  had to wait. One run at a time. RAM use before each run was 64.5 to 69.6% (after: 64.4 to 69.6%). Total CPU use
  sampled while idle was 15 to 19% (background node and python services of other tools, and two idle MSBuild nodes
  from other sessions, which I did not touch).
- Figures are the median of the runs' medians, with the range in brackets. Every run is listed in the raw numbers
  below.

1. **D2 React/Babel ordinary limit (50 ms):** 2 of 9 rows over in runs 1 and 2, 1 of 9 in run 3. Over rows were
   `library-card-03` in all three runs (101.2, 52.3, 55.1 ms), `pantry-react-jsx` in run 1 (62.6 ms) and
   `library-card-09` in run 2 (129.2 ms). The median is well inside the limit.
2. **D6 Mermaid ordinary limit (50 ms):** `library-card-02` in run 1 only (61.2 ms). 9 of 9 in runs 2 and 3.
3. **D4 D3 chart/canvas limit (60 ms):** 3, 4 and 1 rows over, 6, 5 and 8 of 9 within. Over rows: run 1
   `library-card-02` 73.5, `-03` 62.3, `-06` 64.9 ms; run 2 `-02` 77.5, `-04` 62.3, `-08` 69.7, `-10` 78.8 ms; run 3
   `-02` 66.1 ms. The D4 median (53.1 ms) is under the limit but is only 7 ms from it.
4. **D5 Chart.js limit (60 ms):** `library-card-02` in run 2 only (63.3 ms).
5. **D7 Phaser limit (180 ms):** `library-card-02` in every run (242.7, 294.1, 246.4 ms), so 8 of 9 rows. Memory was
   within 130 MiB in all rows.
6. **Animation frame with a whole-surface copy:** 9.2 ms over the 8 ms target. This is the "before" comparison row the
   benchmark keeps for the damage-rect work, not the shipped path (the shipped damage-rect row meets).
7. **Scroll frame by full repaint:** 12.6 ms over the 8 ms target. This is the fallback when retained scroll cannot
   be used (for example a page or scale it refuses). The normal path is the retained row,
   which meets the target at every scale.

No miss on the visible first-paint budget, the headless figure, D1 start-up, either canvas probe, or the hover
budget.

## Surprising or worth knowing

- Several figures moved a lot against 0.9.0: animation frame 10.2 to 6.2 ms, hover 5.4 to 3.2 ms, scroll 19.3 to 1.6 ms,
  visible first paint 60.2 to 65.7 median / 160 to 173 p95 to 42.8 to 45.4 / 80.5 to 107.0, D7 canvas p95 19.8 to 9.9 ms,
  D7 start-up 238 to 145 ms. The 0.9.0 scroll figure was a full repaint; the retained path is now the shipped row, and
  the full-repaint row (12.6 ms) is the like-for-like comparison.
- Scroll was measured at all five default Windows scales (100, 125, 150, 175, 200%): the benchmark supports them and
  the 100 to 200% range stays within 1.6 to 2.3 ms.
- The slowest row of a class is repeatedly the first row measured (D2 `library-card-03`, D4 `library-card-02`, D7
  `library-card-02`). That looks like a first, uncached load, but I did not investigate the cause. Limits are checked
  per row on a single sample, so these rows count as misses.
- D5 `library-card-*` rows cost 0.02 ms per frame: they draw nothing on the ticks, so the D5 canvas figure is in
  practice the one animated page, `canvas-animated-bars`, at up to 5.3 ms.
- The first run of D1 had the slowest cold start (272.5 ms against 198.1 and 249.9 ms); all three are under 400 ms.
- The visible p95 varied more than the median across runs (80.5 to 107.0 ms against 42.8 to 45.4 ms): that is the tail
  of 24 fixtures, so one slow fixture moves it. It is under 150 ms in all three runs.
- Hover run 1 had a single p95 of 7.9 ms (the other two runs 3.8 and 4.1 ms) while its median was 3.4 ms.

## How each was measured

- **Paint budgets:** `Folio.Benchmarks.exe bench 5 30`, three separate processes. The `5` is the parse-stage run count; the
  frame measurements use 30 frames each after ten warm-up frames and two full discarded passes before the measured
  pass (the benchmark's `Steady`), so JIT is warm. I did not find a separate "5 warm-ups" setting: this is the
  command the benchmark exposes. 800x600 at scale 1; scroll at 100, 125, 150, 175 and 200% in the same command.
  The "typical dashboard", "card hover restyle" and "viewport scroll frame" rows are the headline figures; the copy
  variants are shown separately.
- **Visible first paint:** `tools/Folio.WinForms.Benchmarks <repo>\tests\conformance`, three runs, 24 S1/S3 fixtures
  (12 each), five samples per fixture, 1920x1080 client at 96 DPI. The median and p95 are over the 24 fixtures
  (nearest rank).
- **Headless first paint:** `Folio.Benchmarks.exe firstpaint 5 on`, three processes; the figure is the
  `PROCESS corpus median/p95` line (the first round in a fresh JIT process). No window, so presentation to a control
  is not included.
- **Start-up:** `FOLIO_CONTENT_HOST=artifacts\content-host\Folio.ContentHost.exe Folio.Benchmarks.exe scripted` (D1)
  and `... scripted --libraries` (D2 to D7), three runs each. Limits are in [start-up-limits.md](../start-up-limits.md):
  50 ms / 80 MiB ordinary (D2, D3, D6), 60 ms / 85 MiB chart/canvas (D4, D5), 180 ms / 130 MiB Phaser (D7). The
  library benchmark exits with code 1 when any row is over a limit; all three runs did. First frame is a warm reload
  in one long-lived process, so it is not a user's first visit to a library.
- **Canvas probe:** `artifacts\canvas-frame-probe\Folio.Benchmarks.exe 30`, three runs. Each run's figure is the median
  of four internal runs of 30 frames, p95 per artifact, "Total" column.
