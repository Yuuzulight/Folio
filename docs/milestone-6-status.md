# Milestone 6 status

Milestone 6 is **in progress**. The earlier completion announcement and issue closures did not establish the original acceptance criteria. See the [issue-by-issue audit](milestone-6-audit.md) for all 45 original issues and their remaining requirements.

## Verified during the 2026-10-18/19 audit

Native Windows adapters now have direct runtime regression checks. `MediaFoundationAudioDecoder` decodes WAV/MP3 audio and an H.264 video thumbnail with actual format metadata, end-of-stream handling, bounded output and native cleanup. `WinMmMediaAudioOutput` uses the correct pointer-sized header layout, bounds queued PCM and implements lifecycle commands. Tests exercise real system codecs, concurrent decoding, corrupt/truncated input, queue failures, and silent submission to a local output device where available. Windows CI runs codec checks; Linux runs portable fake-driver and layout checks and skips native-only cases.

These adapters are explicitly host supplied through `FolioOptions.MediaDecoder` and `MediaAudioOutput`; `FolioView.LoadHtml` forwards them for in-process documents. Content-process decoder/output IPC is not wired. A single decoded thumbnail is not moving video playback.

The Jint compatibility backend is now pinned to 4.17.0; direct owner-thread evaluation replaces the blocking-await/background-pump workaround. Native-engine requirements remain separate.

The content process now loads external scripts and fetch resources through the host's configured `IResourceLoader`, preserving resource kind and integrity metadata. An optional `ContentResourcePolicy` adds restrictions; absent a loader, requests are refused. Replies are correlated and capped at 8 MiB of binary data, and queued commands share a 32 MiB limit. The reader can receive replies while document execution waits for them. Heartbeat acknowledgements are terminal and remain ordered behind document work, preserving the watchdog. HTML loads use the normal script runner once and create fresh document/engine state; navigator metadata installation preserves installed feature APIs. Real child-process regressions cover these paths. Persistent artifact storage now has a semantic process broker; media adapters still lack one; continuous event-loop/rendering and input delivery need separate end-to-end verification.

Workers, MessagePorts and global `structuredClone` now use one graph codec rather than independent JSON implementations. Tests cover rich graphs and transferred views, sender detachment, receiving-engine port wrappers, moved mailboxes, worker-owned callback threads, private intrinsic capture, shared pending-message budgets, allocation refusal and subsequent recovery, independent listeners and deep teardown. The HTML port delivery and structured-data algorithms are the behavioral references ([messaging](https://html.spec.whatwg.org/multipage/web-messaging.html), [structured data](https://html.spec.whatwg.org/multipage/structured-data.html)). Buffer transport still copies through base64; this does not establish native zero-copy performance, the native second engine, iframe cross-context messaging or complete browser conformance. Issue #540 remains open.

The 2026-10-19 messaging repair adds 36 regression cases. The final Release solution run passed 3,047 tests, with five environment-related skips and no failures. An isolated scripting run pinned to one CPU with four reported processors passed all 593 cases without changing execution or delivery deadlines. Three fresh reviews completed after the final correction. The event-allocation regression was also checked against disabled cleanup: it failed from retained mailbox storage, then passed with cleanup restored. These are regression results, not proof of the missing original M6 backends.

The 2026-10-20 Cache API repair adds a native transactional ledger with matching, metadata/body preservation, atomic batches, persistent quota accounting, artifact isolation and legacy migration. The content process now shares this host ledger rather than replacing stale serialized snapshots. Real-process tests prove restart persistence without network, concurrent writes, service-worker cache writes, failed commits and bounded chunk transport. Three restarting reviews completed after the corrections. The Release solution run passed 3,097 tests with one local symbolic-link privilege skip; an isolated one-CPU run passed all 638 scripting tests with unchanged deadlines. Cache and IPC fuzzing passed 838,740 and 2,955,391 mutations respectively. [Storage configuration](cache-api-storage.md) documents the atomic host contract, limits and legacy migration boundaries. #558 remains open with its dependency on the separate isolated-service-worker integration.

## Remaining acceptance work

- WebGL resource state and limited triangle drawing exist, but GLSL validation/execution and a GPU backend do not.
- Media still needs timed video frames, synchronized audio/video and content-process IPC, full state-machine/sound-grant behavior and full process-budget verification. Source bytes plus decoded pixels/PCM now share document reservations checked before decoder creation, including reload, capability revocation and teardown. Poster/capture allocations and actual sandbox enforcement still need coverage. Mute/volume, script seeking, replay, loop tails and binding teardown now have direct regression tests.
- Workers now own persistent threads and event loops with timer/microtask globals and parent-loop delivery. Full worker-global coverage, native second-engine checks, aggregate memory enforcement and zero-copy transfers remain unproven.
- WebAssembly is a JavaScript interpreter on Jint, not the native engine required by the issues; its compilation cache is an in-page map.
- Iframes now run permitted scripts in isolated child engines and retire them on navigation/revocation/parent teardown. Sandbox/origin and inherited host-adapter tests pass; actual cross-context messaging, shared nested-frame limits and process-watchdog acceptance remain incomplete.
- Camera/microphone output is synthetic, and WebRTC is in-page loopback without a permitted device/network transport backend.
- Service-worker handlers run in the page engine, document subresource interception is incomplete, and the conformance runner now recreates a fresh page with persisted storage and an offline artifact loader, but real service-worker interception across that reopen remains unproven.
- The capability matrix does not yet execute the complete real process sandbox suite once per feature.

Existing Release tests and D8–D14 images are useful regression checks for the behavior they exercise. Passing them does not resolve missing backend or lifecycle requirements. Dependency-first delivery remains the plan; replacing mature dependencies with Folio-owned implementations is a later, separate track.
