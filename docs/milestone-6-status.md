## Remaining acceptance work

- A native Windows ANGLE GPU backend now has a locally verified trusted clear-colour path, including sandboxed frame composition, resource reservations and process-memory measurement. Native WebGL shader compilation/linking, typed objects, buffers, signed and unsigned integer uniforms/vertex constants, uniform-buffer bindings, vertex state, draw execution, immutable and mutable 2D/cube-map/3D/2D-array texture storage and updates, integer 3D texture sampling, framebuffer-copy/blit/layer attachment, multisample renderbuffers, clear-buffer overloads, byte/float/packed-RGB565 readback, 2D/3D mipmap generation, and the native loss/restore transition are wired and directly tested. Complete WebGL 2 resources, full texture/renderbuffer format/target coverage, budget/device-reset loss, and host-switch acceptance remain unfinished; compatibility state is still used for those gaps.
- Media still needs synchronized audio/video output pacing, full state-machine behavior and full process-budget verification. The decoder contract now accepts bounded timestamped video frames, playback selects the active frame from the virtual media clock while retaining the sequence under the shared budget; focused broker tests and an isolated content-process regression cover host decode plus audio start/submit delivery. Source bytes plus decoded pixels/PCM now share document reservations checked before decoder creation, including reload, capability revocation and teardown; host/data-URL MIME types are forwarded to the decoder. Poster encoded bytes and decoded pixels now use a byte-only shared-budget lease and are released on replacement, reload and teardown; identical static source/poster sharing, external poster image-kind routing, and srcObject capture allocations have direct regressions. Standalone render goldens cover video frames for fill, contain, cover, none and scale-down, plus paused posters. Actual sandbox enforcement, synchronized output and complete process-budget verification remain open. Mute/volume, script seeking, replay, loop tails, independent sound grants and binding teardown now have direct regression tests.
- Workers now own persistent threads and event loops with worker-only platform globals, nested workers, live capability propagation and parent-loop delivery. Full worker-global coverage, proper module execution and asynchronous startup, native second-engine checks, aggregate memory enforcement and zero-copy transfers remain unproven.
- The compatibility WebAssembly surface remains a JavaScript interpreter on Jint with an in-page compilation map; the granted native path is now Wasmtime-backed for the verified numeric/memory/global/local-table subset. The native engine is still not complete for the full issue scope.
- Iframes now run permitted scripts in isolated child engines and retire them on navigation/revocation/parent teardown. Sandbox/origin and inherited host-adapter tests pass; parent/child windows exchange structured messages through the isolated bridge, including a transferred `MessagePort` round trip. Nested contexts now share the root document's aggregate iframe budget; process-watchdog acceptance remains incomplete.
- Camera/microphone output is synthetic, and WebRTC is in-page loopback without a permitted device/network transport backend. Capture-indicator retirement after abrupt process termination/replacement still needs acceptance coverage.
- Service-worker handlers now run in a separate worker engine for both in-process and brokered content documents. Registrations persist their scope index and are restored into a fresh document before fetch, with regressions proving an offline fetch, stylesheet and image loads are intercepted after reopen. A brokered content-process regression proves page-only globals remain unavailable while cache writes still reach the host. A direct media regression proves a controller response reaches an audio element's decoder and ready state. Font and child-document decode/navigation evidence and the full sandbox matrix remain incomplete.
- The Windows per-capability base sandbox suite passes locally in all twelve rows, with the same matrix configured in CI. Feature-specific sandbox additions remain part of each unfinished backend's acceptance.

Existing Release tests and D8–D14 images are useful regression checks for the behavior they exercise. Passing them does not resolve missing backend or lifecycle requirements. Dependency-first delivery remains the plan; replacing mature dependencies with Folio-owned implementations is a later, mandatory phase tracked as Milestone 7.
